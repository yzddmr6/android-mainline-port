# 传感器、相机、视频硬解

## 推荐路线

**传感器（高通 SSC，传感器在 SLPI 或 ADSP 的 sensor_pd 上）**
FastRPC → hexagonrpcd（开源，打补丁）→ libssc → iio-sensor-proxy（带 SSC 支持的版本）→ 桌面合成器。传感器校准和配置（registry）从 Android 数据分区只读导入，属于本机唯一数据，不进公开仓。优先复用同 SoC 或同代社区的补丁集。

**视频硬解（高通 Iris/Venus）**
上游驱动 + 本机签名固件（覆盖默认固件名）+ 编成模块 + 设备树启用节点；用户态补齐 GStreamer 插件。

**相机**
先确认上游有没有该 SoC 的相机子系统（CAMSS）和相机时钟控制器；没有时通常要等社区或上游，首版标为不支持。

## 完成标准

- 旋转：四个方向分别记录实际摆放、原始数据、SensorProxy 输出、合成器状态、截图，五者一致；全新安装首次启动无需手动操作。
- 视频：逐帧与软件解码结果一致（例如对比每帧的 MD5）；应用能用到硬解。
- 相机：真实场景拍出正确图像。出现 `/dev/video*` 不算。

## 坑

### 自动旋转的每一层都可能坏
标记：【耗时】
- 现象：横放时画面倒置、竖放不转；D-Bus 值变了但桌面不转；每次刷机后坏一次；首次安装后传感器为空。
- 原因（每层各一例）：安装矩阵用理想值猜；霍尔开关提交在重建内核分支时丢失、极性反；polkit 在登录瞬间拒绝合成器的请求；合成器只在 SensorProxy 名字出现那一刻申请，固定延时解决不了；iio-sensor-proxy 的 SSC 实现有重入问题；hexagonrpcd 缺方法或大缓冲区处理（导入上游提交解决）；远端处理器约 2 秒自动启动，而配置要 20–40 秒后才可读。
- 怎么解决：内核关闭该远端处理器的自动启动，由用户态服务在配置可读后启动一次；矩阵四向实际摆放确认；polkit 规则；等合成器服务名出现后再操作。
- 提前预防：一次启动内不要重启 DSP；测试框架要确认失败真的会报失败；测试用例的顺序可能掩盖序列化错误，打乱顺序再跑一次。
- 适用范围：高通 SSC + GNOME；2026。

### 键盘吸附时不旋转、借用固件画面时不旋转
- 原因：Mutter 只在平板模式开关为 ON 时管理方向；simpledrm 的 Unknown 连接器不支持旋转。都不是传感器问题。
- 适用范围：GNOME；2026。

### 传感器在其他用户的设备上导致远端处理器复位
- 怎么解决：提供关闭开关作为规避，并收集日志。
- 适用范围：SSC；2026。

### 视频硬解没有输出帧
- 原因：借用相邻 SoC 的平台数据时，某条固件消息（例如 RESUME）的负载格式与厂商不同。
- 怎么确认：先 `strace` 看 V4L2 调用（QBUF、STREAMON、DQBUF），再看固件消息收发。
- 怎么解决：按厂商下游的消息序列修正平台数据。
- 适用范围：高通 Iris；2026。

### 多媒体驱动一次性全部编进内核，几张镜像都起不来
- 原因：首要嫌疑是相机时钟控制器第一次 probe 就挂死。
- 怎么解决：多媒体相关驱动编成模块；新时钟控制器第一次用模块方式手动加载。
- 适用范围：高通；2026。

### 相机传感器型号判断错误
- 怎么解决：以 probe 读回的芯片 ID 和官方头文件为准，不按 vendor 库名猜；CCI 地址注意 7 位与 8 位表示（`>>1`）。
- 适用范围：通用。

### 传感器测试必须在新启动上判断
- 原因：ADSP 的传感器 PD 每次 ADSP 启动只读一次配置，状态跨 hexagonrpcd 重启保留。
- 怎么解决：每组测试前重启，记录启动 ID，不在旧状态上判断；配置文件服务要提供原厂 ODM 目录并允许写整个 registry 父目录（到临时副本）；大于 256 字节的写入需要 hexagonrpcd 的上游修复。
- 提前预防：导入本机传感器配置时拒绝过期副本（以设备上的最新版本为准）。
- 适用范围：高通 SSC；2026。

### 相机能取帧，但应用里看不到相机
- 现象：测试脚本取到 30 帧实景，Snapshot 等应用里没有相机。
- 原因：缺少相机守护服务（例如 camerad 的系统服务），PipeWire 列不出设备。
- 怎么解决：验收要走到用户实际使用的应用入口；取帧通过不能关闭"相机不可用"。
- 适用范围：libcamera + PipeWire；2026。

### 相机自动对焦执行器不响应
- 原因：执行器电源电压不在主线 regulator 步进上，又缺本机寄存器证据。
- 怎么解决：不要猜邻近档位；先只读原厂电压寄存器，确认后再启用；在此之前不启用自动对焦。
- 适用范围：VCM 执行器；2026。

### 相机重启后一直 `-EPIPE`
- 现象：密集测试后 media pipeline link validation 失败，跨相机服务重启持续。
- 可能原因：路由函数忽略 link-disable 失败提前返回，残留的 link 和 ACTIVE 格式。
- 状态：未定位。
- 适用范围：libcamera 软件 ISP 路线；2026。

### 视频驱动卸载死锁，正常重启卡在关机
标记：【致命】
- 现象：`rmmod qcom_iris` 卡住；随后 `systemctl reboot` 时 USB 断开、设备再也不回来。
- 原因：卸载路径持有核心互斥锁等待中断线程结束，中断线程又在等同一把锁。
- 怎么解决：内核侧按上游在审补丁修正锁序；测试侧不要无人值守卸载或重绑真实硬件驱动，新模块在重启前暂存、用新的 RAM 启动验证；重启前检查 D 状态任务，有就用 SysRq（s、u、b）。
- 适用范围：高通 Iris；2026。

### 视频编解码的语义缺陷：能起流不等于结果对
- VP9 慢速消费时提前结束：时间戳元数据的回退越界，伪造了"最后一帧"标志。用"慢消费者"测试（每帧延迟读取）才能暴露。
- AV1 丢首帧：容器里的 `av1C` 被当成码流送进解码器。
- 变分辨率时有的播放器提前结束：驱动把正常的空 PSC_LAST 缓冲同时标成 `LAST|ERROR`，错误返回还跳过了 EOS 和 last-buffer 状态更新。区分空控制缓冲和坏图像，带 ERROR 的 LAST 也先记完结束状态。
- 请求关键帧无效（`V4L2_CID_MPEG_VIDEO_FORCE_KEY_FRAME` 返回成功，码流里仍只有开头一个关键帧）：控件没有转发到固件，采用对应代际的上游支持。
- 做法：解码每种格式都做快、慢两种消费，并逐帧与软件解码对比；编码由独立的软件解码器读回，核对帧数、关键帧位置和分辨率切换；默认播放器选择 V4L2 硬解要确认。
- 适用范围：高通 Iris + GStreamer；2026。

### 相机迁移或换代后起流零帧，每次 `CSID reset timeout`
- 原因：资源重组（例如换成独立的 PHY 驱动、换公共时钟表）之后，CPAS 的 AHB 时钟没有消费者了，没人再打开它。
- 怎么解决：把需求放回真正的消费者生命周期（例如 CSID 的父 VFE），核对迁移前后的资源所有权，用真实帧验证；不要延长复位超时。"公共表里有相似平台"不能证明资源等价。
- 适用范围：高通 CAMSS；2026。

### 相机的帧率、消隐、增益、裁剪信息不对
- 现象：负的 HBLANK/VBLANK；元数据推算的帧率和实测差很远；裁剪被报成方形；帧率按比例偏低，预览处理开销很大；画面倒置或颜色不对。
- 原因：传感器的计数域（HTS/VTS、像素时钟）和输出域（输出像素、行）混用，增益单位与消费者不一致；寄存器 PLL 表按另一种输入时钟设计；小分辨率预览仍按全分辨率读出再软件缩放；读出翻转改了 Bayer 相位却没有同步报告。
- 怎么解决：对外统一 V4L2 单位，按模式换算寄存器计数，联动曝光上限；分别给出 native、crop、bounds；把 MCLK、PLL、pixel rate、link frequency 和实测帧率交叉核对；提供有原厂依据的 binning 模式；驱动导出翻转控件并报告对应的 Bayer 顺序，设备树写实际安装方向，让 libcamera 协商。数值来自本机。
- 适用范围：表驱动的相机传感器 + libcamera；2026。

### 软件 ISP 的自动曝光和画质
- 自动曝光不能按帧对齐：采集驱动缺帧开始（SOF）事件，libcamera 只能立即写曝光；补上后日志出现 `Using frameStart signal from ...`。
- 固定场景下增益来回调、亮度阶跃后迟迟不稳：目标亮度在高光阈值两侧硬切换，单一更新速度兼顾不了抑噪和跟随。目标连续化、限制稳态步长，持续大误差时进入有界的快速捕获；分别用阶跃响应和稳态噪声验证。
- 暗场越调增益越不亮：自动黑电平估计把有效信号扣掉了，先用暗帧测黑电平和位深量纲。直接导入原厂颜色矩阵反而偏色：它的前提是原厂的白平衡和镜头阴影校正，要连同这些一起评估。
- 消费者按申请的缓冲容量和固定偏移处理帧：读回实际格式，按 `data_offset`、`bytesused` 检查有效区，拒绝元数据不完整的帧。
- 适用范围：libcamera 软件 ISP；2026。
