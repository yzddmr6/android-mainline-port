# 音频

## 推荐路线（高通 AudioReach / ADSP）

1. **前提**：ADSP 固件加载（PAS）、QRTR、PD mapper、GPR 都工作。PD mapper 报 "no support for the platform" 先查根 compatible 是否被改写。
2. **确认拓扑**：从原厂运行时设备树和 mixer 配置确认扬声器后端（TDM 还是 I2S）、功放型号和数量、麦克风类型（数字麦克风直连 LPASS，还是模拟麦克风经 codec 和 SoundWire）。
3. **复用**：优先使用社区已经跑通的同 SoC 后端和功放驱动；拓扑用固定版本的 audioreach-topology 编译；原厂 ACDB 可以解析出后端参数。
4. **逐层推进**：open → hw_params → prepare → DSP 接受播放图 → 功放启动 → 不可闻的全零播放测试 → 电气回环 → 人耳。
5. **UCM 和 PipeWire**：在全新系统上验收；多声道扬声器需要配置 PipeWire 的上混。
6. **音量**：首次出声用保守增益，产品增益单独决定。

## 完成标准

- 播放：指针正常推进、错误计数为零、功放寄存器读回正常（上电、DAC 运行、芯片 ID）、调参文件版本正确、一次启动内没有任何功放或 DSP 错误。
- 机器证据：电气回环或设备自身麦克风录到测试音。
- 人耳：在约定好的时间窗口播放明显可听的测试音，用户确认；多扬声器要分别确认每一路。
- 麦克风：外部声源的出现和消失与录音对应，并有无声源的对照。
- 全部在全新安装（没有保存的 ALSA 状态）上通过。

## 坑

### 和原厂只有一处差异时，最先验证它（例如 TDM 位时钟极性）
标记：【高频】【耗时】
- 现象：播放图能打开，TDM 参数被接受，但 DSP 启动端口失败或功放不出声。
- 原因：位时钟（BCLK）极性或时钟属性与原厂不一致；这类差异容易被判断为"只影响数据"而排到后面。
- 怎么解决：把本机原厂配置和自己的配置逐项对比，"唯一的差异"最先单变量验证。
- 适用范围：TDM 功放；通用方法。

### 音频配置按根 compatible 选择，永远选不中，测试却显示通过
标记：【耗时】
- 现象：功放上电、PCM 能打开、测试"通过"，用户听不到。
- 原因：quirk 选择器写的是根 compatible，被 bootloader 改写；准入测试只看 prepare 的返回值，没看异步日志。
- 怎么解决：quirk 改用声卡名选择；准入改为一次启动内出现任何功放、APM、ADSP 错误都判失败。
- 提前预防：选择器失效后在整个子系统里搜同类条件。
- 适用范围：通用。

### 远端处理器崩溃原因被吞掉
- 现象：ADSP 反复重启，看不到原因。
- 原因：上报崩溃原因的消息字段长度声明错误，原因被丢弃。
- 怎么解决：先修好原因上报，再根据崩溃地址（反汇编 Hexagon 代码）定位；不要先改格式或时序。
- 适用范围：高通 remoteproc；2026。

### 前端和后端的格式、声道数没有交集
- 现象：open 返回 `EINVAL`，prepare 报 `Invalid channels (8)`，只有 debug 级日志。
- 原因：前端只给 S32 而 q6apm 只支持 S16/S24；主线 AudioReach 前端拒绝超过 4 声道。
- 怎么解决：前端用 2 声道 S16，在 DSP 内用通道混合模块按原厂矩阵展开到多路功放。
- 提前预防：离线检查要覆盖平台 PCM 能力约束，构建时检查拓扑的格式和声道。
- 适用范围：高通 AudioReach；2026。

### 功放在位时钟出现之前启动
- 现象：功放启动失败，升压反复复位。
- 原因：功放在 DAPM 的上电前阶段启动，而 TDM 位时钟要到 trigger 时才有；PRM 投票的位时钟 ID 也可能不对。
- 怎么解决：功放在 trigger 时解除静音（`mute_unmute_on_trigger`）；投正确的 TDM 位时钟 ID。
- 适用范围：TDM 功放；2026。

### 上游拓扑片段的端口号为 0，链路被丢弃
- 现象：ADSP 拒绝打开播放图（error 1）。
- 原因：用了一个上游没有设备用过的流图变体，写端口号为 0。
- 怎么解决：修正拓扑并加一个拓扑结构检查工具，构建时检查端口和连接。
- 适用范围：audioreach-topology；2026。

### 每颗功放的调参文件从未加载
标记：【耗时】
- 现象：日志提示加载的是通用调参文件，版本或算法号与 wmfw 不符；长期被忽略。
- 原因：主线 `wm_adsp` 只在 ACPI 设备上把功放前缀拼进文件名，设备树设备总是请求通用文件；文件名会被转成小写。修复补丁没有导出到补丁序列，重建内核分支时丢了。
- 怎么解决：修驱动让设备树设备也按前缀请求；验收时读日志里实际请求的文件名。
- 提前预防：固件版本或算法不符的警告一律当问题处理；所有修复进入补丁序列。
- 适用范围：Cirrus 等带 DSP 的功放；2026。

### 音量明显偏小
标记：【高频】
- 现象：最大音量只有原厂的几分之一。
- 原因：首次出声时为了安全设的低增益被带进正式版；功放驱动默认增益偏低（例如 −24 dB）；原厂能开得更高是因为有 ADSP 扬声器保护；UCM 不导出硬件增益，桌面滑块只调软件音量。
- 怎么确认：读功放增益寄存器的实际值，与原厂播放时的值对比。
- 怎么解决：安全增益和产品增益分开配置；增益是疑点时，在已知安全的范围内直接测一个有区分度的点（例如安全上限），不要每次加 6 dB 慢慢试；原厂在扬声器保护算法下用的增益不算安全点；没有扬声器保护时提高增益有过热风险，给出数值链（寄存器值、dB、功率倍数）和风险由用户决定，并在文档写明。
- 适用范围：多功放平板；2026。

### 多扬声器只有一半出声
- 现象：立体声播放时下方一对几乎无声。
- 原因：PipeWire 默认不把立体声送到后两个声道。
- 怎么解决：PipeWire 配置开启上混（例如 `channelmix.upmix`）。
- 适用范围：四扬声器；2026。

### 全新安装只有 "Dummy Output"，或加一个输出后麦克风一起消失
标记：【高频】
- 现象：开发机正常，新用户装完没有声音设备；或者新增一个默认输出、接上外接显示音频后，只剩 `off`/`pro-audio`，HiFi profile 连同麦克风消失，内核报 `no backend DAIs enabled`。
- 原因：PipeWire（ACP）先设置 verb、立刻打开全部设备的 PCM 做探测，之后才执行设备段的 EnableSequence；FE→BE 路由如果写在设备段，探测时 PCM 打不开，一个 PCM 失败就丢掉整个 profile。开发机因为保存过 ALSA 状态，或手动 `alsaucm` 留下过路由，看不出来。设置一个不存在的控件也会中断整条序列。
- 怎么解决：探测需要的路由放进 verb 的 EnableSequence；可选的控件用 `ControlExists` 保护，必需的路由和增益控件缺失时要明确失败；默认 verb 不包含未验证的输出。
- 提前预防：UCM 和所有依赖保存状态的功能，都在没有 `/var/lib/alsa/asound.state` 的全新系统上验收；首次会话、关掉扬声器后麦克风是否还在、挂起后录放各测一次。
- 适用范围：UCM + PipeWire；通用。

### 只做 prepare 的录音设备探测，偶发让 DSP 整体停止响应
标记：【耗时】
- 现象：开机或登录后偶发所有音频请求超时，随后触控、电量计、UFS、GPU 也出现秒级反复停顿（扩散机制见 `kernel-and-resources.md` 的时钟框架全局锁条目）。
- 原因：录音前端在 PCM prepare 阶段就启动了 DSP 的处理图并排入一批 READ；PipeWire/WirePlumber 探测录音设备时只 prepare、不 start，约 1 ms 后就拆图。prepare 之后不 start 就关闭是合法的调用序列，错在驱动在 prepare 就启动了 DSP 图，造成"刚启动、READ 在途即拆除"，让 DSP 的音频通道停住。
- 怎么确认：分层取证，每轮只回答一个问题、首个超时就停：GPR 收发 → GLINK 事件 → 处理图身份 → 锁持有者；每轮核对探针丢失为零，阴性结论才算数。改了拆除顺序、故障只是换个位置出现时，回头查在途请求和状态，触发因素多半在别处。
- 怎么解决：让驱动对齐 ALSA 语义（prepare 不等于 start）：录音图保持 PREPARED，到 trigger START 才启动并排 READ，启动和首批 READ 的错误向上传。不加重试、延时或 DSP 复位。
- 适用范围：高通 AudioReach q6apm；2026。

### 不放音也到不了最深待机：音频宏驱动常驻持有远端投票
- 现象：s2idle 时长正常，但 SoC 的 CX 塌缩计数不增长；Linux 侧 RPMh trace 看不到阻塞的票。
- 原因：LPASS 的宏驱动从 probe 起就 prepare 投票时钟，票经 PRM 记在 ADSP 一侧，闲置时也不释放。
- 怎么解决：采用上游的 runtime PM 生命周期，让闲置的宏释放投票；用 CX 驻留和唤醒后的录放验证。释放投票之前先满足平台前提（例如缓存控制器分片表正确，见 `power-and-time.md`）。不要从"声卡在、没有播放进程"推定没有音频票。
- 适用范围：高通 LPASS + AudioReach；2026。

### 麦克风读不到数据，所有组合都失败
标记：【耗时】
- 现象：`arecord` 首次读取 EIO，内核无日志；穷举所有麦克风通道都失败。
- 原因：主线 DSP 只读取固定的 DMA 通道（通道掩码由声道数决定），照抄厂商的抽取器编号（依赖一个主线没有的通道映射控件）就会失败；另外也可能把模拟麦克风误判为数字麦克风。
- 怎么解决：与同 SoC 已工作的参考配置逐项对比；改用主线 DSP 实际读取的通道。负对照：只把通道换回去，错误应该重现。
- 提前预防：穷举全部失败，说明有一个共同的固定参数错了。
- 适用范围：高通 LPASS；2026。

### 麦克风判据设计错误
- 现象：安静房间里录音"失败"。
- 原因：判据要求有信号，但没有声源。
- 怎么解决：用外部单音的出现和消失做判据，加无声源对照；或让设备自己播放测试音再录。
- 适用范围：通用。

### ALSA 钩子要求 sequencer
- 现象：USB 声卡或 codec 驱动不自动加载。
- 原因：Ubuntu 的 alsa-base 钩子要求 `snd-seq`，内核没开。
- 怎么解决：`SND_SEQUENCER=m` 并放进模块包。
- 适用范围：Ubuntu；2026。

### PipeWire MMAP 预填死锁被自写测试工具掩盖
- 原因：为了绕过一个问题在 PREPARED 阶段加的门控导致 PipeWire 卡在预填；自写工具是 START 之后才写数据，所以测不出来。
- 怎么解决：根因修复后撤掉门控；验收用真实的 PipeWire 路径。
- 适用范围：通用。

### 用厂商遥测值判断有没有输出
- 原因：厂商功放的输出功率、电压监测值不能当输出判据。
- 怎么解决：用电气回环、录音或人耳。
- 适用范围：通用。

### 功放驱动要求一路原厂并不存在的电源
- 现象：功放驱动不 probe，binding 要求 `dvdd-supply`，而原厂设备树和驱动都没有这路电源。
- 怎么解决：临时用一个无电压的占位 `regulator-fixed` 让驱动加载，并登记技术债；真实供电确认后替换。
- 适用范围：AW88261 等；2026。

### 小知识
- AudioReach 的部分 mixer 控件写 `on,on` 读回 `on,off` 是正常的（只实现了第一个值）。
- 测试流没被 WirePlumber 自动链接时，先查节点属性和策略日志：裸测试流常缺 `media.type`、`media.category`、`media.role`（例如 `pipewiresrc` 测相机时要用 stream-properties 补上）。

## 未解决

- 启动阶段偶发的功放上电错误是否无害。
- 投票时钟在全局 `prepare_lock` 里同步等远端的结构问题：触发序列已修，扩散路径仍在。
