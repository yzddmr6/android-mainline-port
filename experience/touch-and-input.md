# 触控、按键、键盘配件、手写笔、指纹

## 推荐路线

**触控**先判断形态：
- 独立触控芯片、固件在芯片 flash 里：驱动相对独立，按普通 I2C/SPI 外设处理。
- 显示触控一体（TDDI）、固件在 RAM 里：面板复位会让触控固件丢失。驱动必须跟随面板电源序列（`drm_panel_follower`），每次面板上电后重新下载固件。
- 原始数据加主机算法（THP）：内核只负责下载固件和传输原始帧，触点由用户态算法计算（需要开源算法实现和本机标定数据）。

步骤：读厂商驱动源码（没有源码才反汇编）和原厂日志里的固件下载流程、命令时序 → 以同系列已进主线的驱动为底 → 节点写法参考同 SoC 设备，数值用本机 → 逐个函数与厂商实现对照帧格式 → 接入面板电源序列 → 标定方向。

**按键**：电源键和音量减通常来自 PMIC PON（`pwrkey`/`resin`），音量加常是 PMIC GPIO 上的 `gpio-keys`。按本机原厂设备树描述，去抖时间按原厂值。

**键盘配件**：从厂商驱动抽出协议，写成 HID 传输驱动或 serdev 驱动；单独一个协议核心加测试；板级补电源、检测脚、方向脚；接入平板模式开关。

## 完成标准

- 触控：真实手指点击、滑动、多指、四角、横竖屏；冷启动、熄屏再亮屏、面板重新上电三种情况分别测；多次冷启动输入设备号稳定。中断计数增长、输入设备存在、程序注入的事件都不算。
- 按键：真实按下和松开的 evdev 事件；桌面出现音量提示或电源键行为符合设置。
- 键盘：真实按键、组合键、拔下再吸附、熄屏后恢复。

## 坑

### TDDI 面板熄屏后触控永久失效
标记：【高频】【耗时】
- 现象：空闲几分钟自动熄屏、再亮屏后触控没反应；SPI 零错误、中断线停在低电平、中断计数不再增长、日志没有任何错误；重启触控服务立刻恢复。
- 原因：显示和触控是同一颗芯片，熄屏时面板驱动拉复位线，触控固件跟着丢失；触控驱动只在服务启动时下载固件。
- 怎么确认：让桌面熄屏几秒再亮屏，看中断计数是否恢复、有没有新的固件就绪日志。
- 怎么解决：触控驱动注册为面板 follower，在面板 enabled/disabling（或 prepared/unpreparing）回调里停流和重新下载固件；面板还没上电时打开设备不能直接失败，要延后到面板就绪。
- 提前预防：之前的触控"通过"如果是在 bootloader 留下的面板状态下测的，显示驱动接管或熄屏功能加入后必须重测。
- 适用范围：TDDI 面板（例如 Novatek NT365xx 系列）；2026。

### 帧长度被截短，固件卡在中间状态，驱动却报告成功
标记：【耗时】
- 现象：驱动打印 "Update firmware success"，但没有中断或数据。
- 原因：社区实现把厂商的状态清理帧、校验使能帧截短；"成功"判断只检查了一个字节的阈值。
- 怎么确认：以本机厂商二进制为准，逐笔对比每个事务的字节和长度；看固件状态机是否到达就绪状态。
- 怎么解决：恢复厂商帧长；成功判断改为检查固件真正就绪的状态值。
- 适用范围：Novatek 等闭源协议触控；通用方法。

### 分段固件漏写第二段头，校验却通过
- 现象：硬件 CRC 一致，状态始终不对，固件信息全零。
- 原因：漏写不在 CRC 覆盖范围内的一段头数据；反汇编时把条件分支读反了。
- 怎么解决：找到厂商源码逐函数比对；先做一个 debugfs 裸 SPI 接口，把十分钟一次的重启实验变成秒级的在线实验。
- 提前预防：能拿到源码就不要反汇编；CRC 通过不代表写入完整。
- 适用范围：分段（cascade）固件的触控芯片；通用方法。

### 触控命令发得太早，返回超时
- 现象：打开数据流时首条命令超时，open 失败。
- 原因：原厂在固件就绪后、数据帧开始输出后才发这些命令（间隔数百毫秒）。
- 怎么解决：等第一帧到达再发命令；按原厂补齐漏发的命令；不要加固定延时或重试。
- 适用范围：THP 类触控；2026。

### SPI 经 GPI DMA 传输报 EIO
- 现象：数据流一开就 `-EIO`。
- 原因：GPI DMA 完成回调先设置了状态，SPI 核心因此不累加 `actual_length`。
- 怎么解决：修正回调里设置状态的时机（内核修复）。
- 适用范围：高通 GENI SPI + GPI DMA；2026。

### 触控在面板上电前 probe，读到全零后连锁空指针
- 现象：双 DSI 面板上，触控驱动在面板就绪前加载，读芯片 ID 为零，随后空指针挂死。
- 原因：fw_devlink 把触控对面板的依赖移交给了主 DSI，SPI 就绪就 probe；`input->dev.parent` 未设置导致 `touchscreen_parse_properties()` 空指针。
- 怎么解决：probe 时不访问硬件，等第一次面板就绪后再读 ID；设置输入设备的父设备。
- 适用范围：TDDI + 双 DSI；2026。

### 触控方向标定反复出错
- 现象：点左上响应在右下，或两轴互换；同一家面板供应商的两批模组方向也可能相反。
- 原因：靠用户回忆的四角点击顺序推映射；内核的处理顺序是先镜像后交换；只看面板供应商名或原厂里全零的翻转字段，选不出正确方向。
- 怎么解决：固定屏幕方向，让用户只做一次单方向滑动，读 libinput 之前的原始坐标推出映射；用通用 `touchscreen-swapped-x-y`、`touchscreen-inverted-x/y` 属性或用户态固定变换，并保留按设备覆盖的开关，默认值保持已有设备兼容。
- 适用范围：通用。

### 音量键没有反应
- 现象：按键无事件。
- 原因：设备树里根本没有描述音量键；或参考设备的引脚和去抖值与本机不同。
- 怎么解决：按本机原厂设备树描述按键：哪颗控制器、哪个 `linux,code`，不要假定音量加、减和 `gpio-keys`、PON `resin` 的对应关系（有的机型 `resin` 是音量加）；去抖时间按原厂；用真实按下的事件确认。
- 提前预防：用户测按键时，用长时间运行的按键记录器代替几十秒的测试窗口，用户什么时候按都有记录。
- 适用范围：高通；2026。

### 键盘配件枚举成功但没有按键数据
标记：【耗时】
- 现象：几个 HID 设备都注册了，版本查询超时，中断为零。
- 原因：缺少原厂常开电源，总线一直低电平（见 `kernel-and-resources.md`）；电压值不在 PMIC 步进上；设备树没写时钟频率时厂商默认 400 kHz。
- 怎么解决：先做电气层判别（拔配件、零传输、引脚切 GPIO、只拉唤醒脚），确认线路电平后再碰协议。
- 提前预防：枚举成功不是进展，要有一个可以随时触发的真实总线自检。
- 适用范围：I2C 键盘桥（例如 Nanosic）；通用方法。

### 键盘协议细节
- 帧头长度、两种校验算法、业务帧前缀不能混用；单线半双工 UART 会收到自己的回波，要校验回波与发出的帧一致才算送达；主机不要先发，等键盘的同步包。
- 新版串口核心多了一层 `<uart>:<ctrl>.<port>` 中间设备，旧诊断工具会找不到。
- 配件上没有的触摸板不要注册；有触摸板的标为外部设备，避免与平板模式冲突。
- 适用范围：磁吸键盘；2026。

### 键盘吸附时屏幕不自动旋转
- 原因：GNOME（Mutter）只在平板模式开关为 ON 时管理屏幕方向，键盘吸附时开关为 OFF。这是预期行为，不是缺陷。
- 适用范围：GNOME；2026。

### 指纹
- 状态映射：只把精确的重试提示映射为 retry，等待类状态不是设备错误。
- 模板文件要求 0600，服务设 `UMask=0077`。
- 判断成败看 PAM、`Session.Unlock`、`LockedHint`，不看驱动日志。
- RAM 启动时首次建立凭据也会写安全存储，不是零写入。
- 和安全世界共享的总线不要交给 Linux。
- 适用范围：QSEECOM + libfprint-TOD；2026。

### 面板上电回调里同步等待触控首帧：亮屏变慢、偶发触控失效、切刷新率后触控死亡
标记：【高频】【耗时】
- 现象：熄屏再亮屏后偶发首帧 500 ms 超时、触控停止（SPI 无错误）；设置里切到 120/60 Hz 后触控失效（`THP first valid frame not received: -110`），切到 90/144 Hz 正常；亮屏整体慢。
- 原因：触控驱动在面板 enable 回调里同步等待第一帧，而这个回调发生在显示控制器开始输出（kickoff）之前，显示提交被阻塞，某些刷新率下首帧永远赶不上时限。
- 怎么确认：同时记录面板回调、显示 kickoff、触控首个中断的时间。
- 怎么解决：回调里只排一个异步工作项，首帧等待放到工作项里，保留时间预算；不要延长超时、不要删命令、不要靠服务自动重启掩盖。用 DRM trace 量 encoder enable 到第一次 commit 的时间，几百毫秒的阻塞一眼就能看出来。
- 适用范围：TDDI/THP 触控 + DRM panel follower；2026。

### 收到第一帧就发模式命令，热重启后触控持续失效
标记：【耗时】
- 现象：冷启动和亮屏都正常，触控服务被杀掉重开后，模式命令不被处理、开流超时；退避重试每次都失败，直到面板断电一次。
- 原因：把"收到一个有效帧"当成"固件可以接受命令"。热重启时面板没断电，固件软复位后重新下载，首帧在固件还处于重新校准阶段就到了；需要正常固件循环的命令只有在复位状态到达正常运行态之后才会被处理。原厂代码在这类命令之前都先检查复位状态。
- 怎么确认：用 SIGKILL 热重启把偶发问题变成确定复现；在就绪日志里分段打印下载、复位状态、首帧和命令的时间。
- 怎么解决：按原厂语义等固件复位状态到达正常运行态再发命令，等待有上限，失败时如实报告最后的状态。看似有效的"先读回一次"只是一段恰好够长的等待，不要采用。
- 适用范围：THP/TDDI 类触控（例如 Novatek）；2026。

### 合盖后要等很久才挂起，或合盖后屏幕被点亮
- 现象一：合盖后直到 `InhibitDelayMaxSec` 上限才挂起；单独注入合盖事件很快，合盖加触摸可以稳定复现。原因：键盘盖贴着屏幕，触摸事件打断锁屏，睡眠延迟锁迟迟不释放。怎么解决：跟随真实的 `SW_LID` 状态停用（inhibit）触摸屏和笔，开盖恢复；原厂通常也这样屏蔽合盖时的触摸。
- 现象二：合盖后隔着盖子按键，屏幕被点亮。查合盖时谁还在把键盘事件交给桌面：键盘驱动有没有按盖子状态停用，libinput 有没有把这块键盘和盖子开关配对。
- 适用范围：带键盘盖的平板 + logind/GNOME；2026。

### 盖子没动，挂起后却被盖子的中断立刻唤醒
- 现象：盖子开着时挂起，进入深睡后被盖子 GPIO 的中断唤醒，输入状态没有变化。
- 原因：`gpio-keys` 的"只在开盖时唤醒"（`EV_ACT_DEASSERTED`）被无条件布防；高电平的 GPIO 经唤醒控制器恢复时锁存了一个边沿。
- 怎么解决：只在入睡时开关确实处于 asserted（盖子合着）才布防 deassert 唤醒，读状态失败时保守处理并能回滚。验证合盖入睡、开盖唤醒、开着盖用电源键入睡三种情况。
- 适用范围：带状态前提的开关唤醒；2026。

### I²C 设备的数据中断被自动设成了唤醒源
- 现象：亮屏后一秒内挂起，会被配件的 MCU 立即唤醒；屏幕稳定后挂起正常。
- 原因：I²C 设备节点带 `wakeup-source` 时，I²C 核心会把它的 `interrupts` 自动设为唤醒源，于是数据中断和驱动专门布防的唤醒脚同时生效。
- 怎么解决：先做首个唤醒 IRQ 的对照确认是哪根线；把唤醒限定在专门的唤醒脚。
- 适用范围：I²C 配件（键盘桥等）；通用。

### 磁吸键盘的电源生命周期要对齐原厂
- 现象：熄屏或休眠后键盘没反应，线路上只有唤醒或加速度帧、没有 HID 帧；断电重新上电能恢复。
- 原因：没有按原厂在熄屏和亮屏时写配件的电源状态寄存器（例如熄屏写 0、亮屏先读后写 1）；用了社区的周期保活和自动复位来掩盖。
- 怎么解决：读原厂驱动的熄屏/亮屏生命周期，按同样顺序实现，删掉周期保活和"丢弃首个中断"之类的绕过。
- 提前预防：同品类配件在不同设备上的协议可以完全不同（例如一种是 UART 主动心跳，一种是事件驱动的 I2C 桥），不能照搬另一台设备的保活策略。
- 适用范围：磁吸键盘；2026。

### GNOME 设置里没有电源键选项
- 原因：GNOME 对 Chassis 为 tablet/handset 的机器隐藏电源键设置（同时挂起被禁用时也隐藏）。
- 怎么解决：把 Chassis 设为 `convertible`（仅在缺失时写，卸载时移除）。注意 convertible 会改变睡眠延迟和空闲睡眠提示等行为；BlueZ 没有 convertible 到蓝牙设备类别的映射，对端会看到"未分类"。
- 适用范围：GNOME 49/50、BlueZ 5.85；2026。
