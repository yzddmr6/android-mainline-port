# USB、Type-C、外接显示、存储、分区、双系统、刷写与安装

## 推荐路线

**USB**：先做设备模式（作为调试通道，USB2 高速 NCM 最稳），再做主机模式和外接显示。启用顺序：控制器角色切换 → UCSI → VBUS → 枚举 → USB3/DP。

**存储与分区**：存储控制器和 PHY 内建；分区一律按 PARTLABEL/GUID 定位。只截 userdata 尾部给 Linux（根分区 + home 分区）。

**双系统**：活动槽镜像集轮换。两个系统都从当前活动槽启动，切换时把目标系统的启动镜像集写入活动槽，另一套存在 Linux 分区里；系统内切换用 `dd`，Android 侧用 KernelSU 模块；开机后标记槽成功。

**根文件系统交付**：设备上格式化 + 解压 tar（保留扩展属性和数字属主）。如果必须发镜像，只编码已用块。

**维护镜像**：一个只在内存里运行、带存储驱动、root shell、分区工具、不挂载任何分区、无会话超时自动回 Fastboot 的小镜像，用于写分区表和首启前预置本机文件。

## 完成标准

- USB：U 盘读写、鼠标、拔插恢复、USB3 速率证据、外接显示器出画面（EDID、模式、拔出恢复），切换后调试通道恢复。
- 分区：写后读回一致，`sgdisk --verify` 通过。
- 双系统：Linux → Android → Linux 在真机上各走通一次，加冷启动；槽属性前后对比。
- 安装：按公开文档在真机上从零走一遍，包括 GNOME 首次设置。

## 坑

### 刷写镜像把空白区域编码成"写零"，刷写极慢，Fastboot 失去响应
标记：【高频】【致命】
- 现象：`fastboot flash` 很快返回 OKAY，后续命令排队几十分钟，甚至设备不再响应；单个分区"刷"了几分钟到几小时。
- 原因：sparse 镜像里的空白被编码为 FILL（写零），bootloader 先回 OKAY 再在后台慢速写零（例如几十 MB/s，几百 GiB 要几小时）；Fastboot 的 OKAY 不代表写完。
- 怎么确认：刷前汇总镜像的 RAW、FILL、DONT_CARE 展开字节数。
- 怎么解决：根文件系统用 tar + 设备上 `mkfs.ext4` 交付；空数据分区在设备上格式化；必须发镜像时按 ext4 位图只编码已用块。
- 提前预防：设计安装流程前先看同类项目的安装器。
- 适用范围：通用；2026。

### sparse 镜像的 DONT_CARE 不清除旧数据，可能导致旧日志被重放
标记：【致命】
- 现象：刷到有旧数据的分区后文件系统异常。
- 原因：`img2simg -s` 把空块标为跳过，设备上保留旧内容；如果文件系统 UUID 固定（例如由发布名生成），重装同一版本时旧日志块校验仍然通过，崩溃恢复时可能把旧日志重放到新文件系统上。文件内部的零块和 inode 表、日志区必须写。
- 怎么解决：只跳过位图标明的空闲块；inode 表和日志区照写；或改用设备上格式化。
- 适用范围：通用。

### 只改 GPT 属性位切换 A/B 槽，两个槽都无法启动
标记：【致命】【耗时】
- 现象：点"重启到另一系统"后约 2 秒进 Fastboot，此后刷原厂镜像、`fastboot boot` 已知好镜像、甚至 4 KiB 全零文件都报同一个错误。
- 原因：bootloader 的槽状态不只是 boot 分区的属性位，还包括各 LUN 上每对 `_a/_b` 分区的类型 GUID 互换和启动 LUN，只改属性位会被 bootloader 的 GUID 校验拒绝。
- 怎么确认：先读 bootloader 记录的失败原因（例如 `fastboot oem fbreason`），同时采 `getvar all` 和 GUID 信息。
- 怎么解决：恢复 GPT 让 bootloader 重建槽状态，再用它自己的 `--set-active`；双系统改用活动槽轮换。
- 提前预防：A/B 状态只经 bootloader 自己的命令改；有效镜像和无效镜像失败方式相同时，立刻停止"镜像内容"类假设；弄清机制前不用改变状态的命令诊断（包括以"回退"为名的 `--set-active`）。
- 适用范围：高通 ABL；2026。

### B 槽或 recovery 分区不能用来放 Linux
- 现象：B 槽启动进旧版本链或失败；recovery 拒绝带内核的镜像。
- 原因：B 槽出厂可能是旧固件链或全零，super 分区只装得下一套 Android；recovery 只被当作 ramdisk。
- 怎么确认：先对比两槽各分区的哈希。
- 适用范围：高通；2026。

### 主机 Fastboot 写槽会重置重试计数，自制系统不标记成功会被判为不可启动
- 现象：多次启动后槽被标为 unbootable。
- 原因：主机 `fastboot flash` 把重试计数重置为 7；Linux 不会像 Android 那样标记启动成功。
- 怎么解决：系统内用 `dd` 写入（保留属性）；开机后用一个服务标记槽成功。
- 适用范围：高通 A/B；2026。

### 双系统安装后 Android 首启失败
- 现象：切回 Android 进入 recovery 或黑屏。
- 原因：Android 依赖的固件分区（modem、bluetooth、dsp）损坏，而安装器只校验了启动链。
- 怎么解决：安装器校验 Android 依赖的所有固件分区；用 rawdump 里的内核日志取证。
- 适用范围：高通；2026。

### 切换工具在写槽失败时删掉了正在使用的镜像集
- 原因：轮换逻辑没有先确认当前活动槽里实际是哪一套。
- 怎么解决：先校验槽内实际镜像的哈希，再决定轮换；写入后读回，不一致就写回原镜像且不重启；写入期间忽略中断信号。
- 适用范围：活动槽轮换；2026。

### "保留 home"选项实际格式化了 home
标记：【致命】
- 原因：主机端接受了参数，设备端脚本没有接收，无条件格式化。
- 怎么解决：格式化前校验卷标并 `e2fsck`；端到端测试证明设备侧确实没有格式化。
- 适用范围：通用。

### 盘符会变
- 现象：同一台设备不同启动的 `sdX` 不同；主线控制器名也与 Android 不同。
- 怎么解决：备份文件名只由当时的清单解释；恢复前用控制器、LUN、GPT GUID、label 和几何重新确认；不要按盘符回写。
- 适用范围：UFS；通用。

### 备份 GPT 的位置写死，bootloader 改写后对不上
- 怎么解决：主备 GPT 的位置都从头部读取。
- 适用范围：通用。

### 备份不完整或不一致
- 原因：GPT 表区有填充；FAT 分区无法冻结；没 root 时无法读原始块；活跃分区读取不是一致快照。
- 怎么解决：用临时 root recovery 或先 root 再备份；主机和设备两侧算哈希；说明备份是"逐分区状态"而不是原子快照。
- 适用范围：通用。

### 刷写后发现缺少本机数据，首启时触控、蓝牙不可用
- 原因：校准、地址等本机唯一数据不能进公开镜像。
- 怎么解决：安装流程里加一步"首启前预置本机文件"（用维护镜像写入）；文档写明首启前后的差异。
- 适用范围：通用。

### 维护镜像里的 HTTP 服务起不来或端口冲突
- 原因：服务在 USB 网络链路起来之前启动；主机上常用端口被其他进程占用。
- 怎么解决：等链路就绪后再启动服务；端口可配置。
- 适用范围：通用。

### 安装环境里的工具缺失或行为不同
- 现象：没有 `/dev/disk`；某些 coreutils 实现拒绝未登记的 UID；`install /dev/stdin` 报错；BusyBox tar 不保留扩展属性；Ubuntu 26.04 的 uutils `dd oflag=direct` 报 Invalid input 或 `EINVAL`（缓冲区对齐，不是存储故障）；产品镜像里没有 `curl`。
- 怎么解决：在真机内存环境里先用小样本跑一遍（格式化、校验、改属主）；用 GNU tar；直写测试换一个确认满足对齐要求的工具对照，或写入后 `conv=fsync` 加清缓存；同一个工具第二次出问题就换工具。
- 适用范围：通用。

### USB 网络传输停滞
- 大文件中途停滞：分片传输（例如 64 MiB 一片），服务端按偏移读同一个已校验文件；任何分片校验失败立即停止。
- 低流量 SSH 小包滞留：`f_ncm` 的发送定时器没有正确处理 `NETDEV_TX_BUSY`，包留在 NTB 里；采用上游的定时器修复，不要在 SSH 或网络服务层周期重启。
- 适用范围：NCM gadget；2026。

### 调试网卡名被外接 USB 网卡抢占
- 原因：外接网卡也叫 `usb0`。
- 怎么解决：configfs 里固定接口名和 MAC，用 `.link` 文件识别。
- 适用范围：通用。

### UCSI 复位命令风暴把 ADSP 打到无响应
- 现象：UCSI 偶发复位超时，之后整次启动 ADSP 不应答。
- 原因：`EPROBE_DEFER` 后每 20 ms 重发一次复位命令，数百次。
- 怎么解决：复位命令只发一次。
- 适用范围：高通 UCSI；2026。

### USB 主机模式不稳定或整机冻结
- 原因：USB3 PHY 参数表与本机代际不匹配（需要整表移植厂商的值）；`maximum-speed` 属性导致越界且会被 bootloader 改回；没设 `allow_userspace_control`；pipe 时钟提前开启。
- 怎么解决：按上述逐项修；可能卡死总线的驱动调试期编成模块。
- 适用范围：高通 DWC3 + QMP；2026。

### 拔掉外接显示器后，USB 设备模式和主机模式都不恢复
- 现象：之后 NCM gadget 绑定报 `-19`（`-ENODEV`），xHCI halt `-110`；控制器在活跃角色的工作里读到寄存器和端点容量全零。
- 原因：DP-only 期间控制器仍在用已经不可用的 PIPE 时钟。
- 怎么解决：DP-only 时切到 UTMI 时钟，SAFE 过渡期间保持正确选择，USB 模式恢复后再切回 PIPE；角色切换、PM 和 mux 的顺序要配套。控制器 runtime 挂起时手工读到的全零不能当同等证据。
- 适用范围：共享 combo PHY 的高通 DWC3；2026。

### 挂起中拔线导致整机复位
- 原因：不可冻结的 UCSI 工作在系统恢复之前就调用角色通知，访问 USB glue 寄存器时它的时钟还关着；系统睡眠期间 `pm_runtime_resume_and_get()` 可能返回成功却没有真正恢复硬件。
- 怎么解决：系统睡眠期间只记录最新的角色变化，时钟和控制器恢复后再应用；用锁串行化通知和睡眠回调。
- 适用范围：DWC3 glue + UCSI；2026。

### 只有一个 Type-C 口，测试主机模式会断开调试
- 做法：切换前在设备上设好定时回退，读回生效后再切；测试 OTG、VBUS、外设之前，先在设备上建立 Wi-Fi SSH 备用通道并验证身份；把换线、插外设这些物理动作集中到一次。
- 适用范围：通用。

### 外接显示链路的若干问题
- 设备树里的切换芯片名与实际芯片不一致（以 I2C 读回 ID 为准）；接口要求位图却填了引脚编号；方向或切换出错时仍上报 HPD 已连接；SBU 切换芯片驱动必须内建；外接显示通常要求内屏已由原生驱动接管。
- UCSI 报告的供电状态是逻辑状态，不代表物理供电。
- 适用范围：高通 DP AltMode；2026。

### 只读识别磁盘时驱动仍会写设备属性
- 原因：UFS 驱动加载时会设置一些设备属性。
- 怎么解决：知道这一点，必要时在原厂确认这些属性的原值。
- 适用范围：UFS；2026。

### UFS 调频时 I/O 永久等待
- 原因：较早的 clock scaling 路径先停 tagset 再等写锁，持读锁的管理命令却需要派发才能完成，互相等待（识别点 `ufshcd_clock_scaling_prepare()`）。
- 怎么解决：采用上游完整的锁序修复（获取和释放两半都要）；不要把任意存储卡顿都归到这里。
- 适用范围：主线 UFS 7.2 前后；2026。

### 紧急切回 Android 之后切不回来
- 原因：写好启动槽后直接 `reboot -f`，ext4 留下 `needs_recovery`，Android 侧只读挂载 Linux 根的切换工具拒绝继续。
- 怎么解决：复用已有的镜像集校验、写入和读回；重启前卸载或只读重挂，必要时走 SysRq 的 sync、remount-ro、reboot。
- 适用范围：活动槽轮换的双系统；通用。
