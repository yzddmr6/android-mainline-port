# GPU 与图形栈

## 推荐路线

1. **内核**：上游 `drm/msm` 对该代 Adreno 的支持（GPU 时钟控制器、GMU、SMMU、OPP 表）。新一代 GPU 常先出现在 linux-next、高通在审系列或社区内核，按来源导入，上游合入后换成正式版本。
2. **固件**：sqe、GMU、zap shader。零售机的安全世界通常拒绝通用签名的 zap，只能用本机原厂签名的文件；有的平台可以先走免 zap 路径验证绘制。
3. **用户态**：先确认发行版 Mesa 是否认识这颗 GPU（看完整 chip id，不只看系列号）。确实缺支持时，基于发行版源码包做最小修补，保留同名包、标准 multiarch 路径、GLVND 和发行版编译配置；GL/EGL/GBM 和 Vulkan ICD 分别核对。独立前缀和环境变量只用于隔离诊断，不作为宿主默认布局。替换包的更新守卫见 `ubuntu-userspace.md`。
4. **沙箱应用**：snap 和 flatpak 用自己的 GL 库，见 `ubuntu-userspace.md`。
5. **新 GPU 的 Mesa 不成熟**：视频纹理、多上下文、Vulkan 路径最容易出问题。跟踪上游 stable 和 main 的修复，按提交回移，并把每个回移登记为技术债，上游发版后换回。

## 完成标准

- 渲染器名称是硬件 GPU（不是 llvmpipe/softpipe），渲染结果逐像素与预期一致。
- 多轮运行时电源切换后仍能渲染；较长时间（例如 200 秒以上）没有 GMU 错误和 hangcheck。
- 桌面合成器实际使用 GPU，帧率接近刷新率。
- 浏览器、视频播放器、设置等复杂应用画面正确，不崩溃；GTK 的 GL 和 Vulkan 渲染器都要测。

## 坑

### 发行版 Mesa 不认识新 GPU，桌面退回软件渲染
- 现象：点击、打字明显延迟；渲染器是 llvmpipe。
- 原因：Mesa 设备表只按完整 chip id 匹配（例如有 `0x44050000` 但本机是 `0x44050001`）。
- 怎么解决：自编 Mesa 并加上设备表修复（上游通常很快有；先确认这个 revision 与已有支持项硬件兼容）；核对完整 chip id；注意别把 APT 候选版本当成已安装版本。
- 适用范围：Adreno 8xx；2026。

### 私有图形库不在标准路径，部分进程静默退回软件渲染
标记：【高频】
- 现象：桌面使用硬件加速，但清空环境的探针、提权程序、WebKit 网页进程或 VMM 的 GPU 进程使用 `llvmpipe`，也可能报 `unsupported GPU id`。
- 原因：库搜索路径和文件系统视图是两道独立门槛。环境变量会被清除；`ldconfig` 能改变宿主搜索顺序，却不能让沙箱看见未挂载的私有目录。为单个程序补挂载只修了一个入口。
- 怎么确认：分别在桌面会话、`env -i`、sudo/pkexec 和真实沙箱进程中核对 renderer、实际映射库与 Vulkan 枚举。沙箱绘制时把进程身份、render node、DRM client 对上，再取同一 client 的 GPU 时间差，要求 `ΔGPU time > 0`；重复 fd 指向同一 client 时去重。映射了含软件后端的 libgallium、WebGL 脱敏字符串或画面正确，都不能单独证明硬件渲染；计数器不可用时明确保留这一验证缺口。
- 怎么解决：用发行版同名包安装到标准路径，移除旧环境注入、私有搜索路径和重复 ICD 注册，保留 GLVND；在上述各类进程环境重验。虚拟化还要核对来宾 renderer 与宿主 GPU 进程，不能用宿主桌面的计数代替。
- 提前预防：默认图形栈按最受限的真实消费者验收，保留软件渲染负对照。此前推荐的独立前缀加 `ld.so.conf.d` 只能解决宿主搜索，不能作为沙箱兼容方案。
- 适用范围：使用宿主库的动态链接程序及沙箱；2026。Snap、Flatpak 等自带运行时仍需各自匹配的 GPU 提供者（见 `ubuntu-userspace.md`），宿主标准路径不保证其加速。

### 文字整片消失，换软件渲染也一样：编译器误编译
标记：【耗时】
- 现象：某个用新渲染后端的应用（例如 Flutter 的 Impeller）图标正常、文字全没了；softpipe 下也一样；开着断言时落在 `ir_constant::is_value`。
- 原因：GCC 13 在 `-O3` 下按 switch 外提循环，丢了 float16 分支，GLSL 编译器的常量折叠算错，mediump 着色器读错了图集通道。
- 怎么确认：先用最便宜、最能区分的对照：换软件渲染、换官方构建的同版本、换架构，把范围从"GPU 驱动"收窄到"自己的构建"；再用编译器包装器加 ccache 做对象级二分。
- 怎么解决：按发行版的编译参数构建（`-O2`），宿主和沙箱提供者一起重建，加一个最小的 GLSL 回归用例。不要用关断言（NDEBUG）把崩溃换成静默的错误结果。
- 适用范围：GCC 13 + Mesa 25/26 aarch64；2026。不能推广成"所有 `-O3` 都不可用"，但没有理由偏离发行版的参数。

### 新 GPU 的计算性能只有原厂的几分之一
标记：【耗时】
- 现象：同频下 Vulkan 计算跑分远低于原厂；GPU busy 高、CPU 空闲，没有报错。
- 原因（一例）：编译器不对运行期次数的循环做部分展开，相邻读取合并不成向量；只读 SSBO 的向量读取走了慢路径。静态 NOP 多不能证明延迟表错了，直接套用上一代的延迟表会产生 NaN。
- 怎么确认：先分清是峰值不够还是某条路径慢（峰值基准不变、跑分大涨说明问题在具体着色器的编译结果）；找一个能工作的参照驱动（原厂驱动、同代 GPU 的其他实现），对同一份 SPIR-V、同样的输入重放，比较 ISA 和单 kernel 时间；在热 kernel 里只换一个变量。
- 怎么解决：只对证实受益的形态启用优化，严格限定条件，让其他着色器的 ISA 逐字不变；每个候选先跑一致性测试子集（例如 Vulkan CTS 的相关部分，几分钟一轮），再看分数。改 descriptor 布局时连 stride 寻址一起改：从二次幂槽数扩成非二次幂后，还用 `log2(stride)` 左移就会让数组第二个元素起寻址错误，自测和跑分照样通过，只有 CTS 能抓到。
- 适用范围：Turnip/ir3 新代际；2026。参照驱动只用来定位，实现自己写。

### GMU 或 GPU 超时：先分清是资源、投票还是中断处理
标记：【耗时】
- 现象：GMU HFI 超时（例如 `HFI_H2F_MSG_GX_BW_PERF_VOTE ... timed out`，随后 `Unexpected message id`）、`Timeout waiting for GMU OOB set GPU_SET`、hangcheck。
- 原因（已确认的几类）：
  - 借用固件画面时显示总线时钟被回收，内存通路降速（见 `kernel-and-resources.md`）。
  - MX 依赖票拿 GMU 自己的 OPP 表去查 GPU 频率，查不到就投 0 档；或电源域投到 retention 档。sync_state 之前各域被钳在最高档，会把这类错误掩盖住。
  - HFI 中断处理把整个状态寄存器清掉，连轮询者在等的消息队列、OOB 应答位一起清了：GMU 其实已经回复，轮询方却判超时；上电后迟到的中断会放大这个窗口。
- 怎么解决：先排除显示侧资源问题，再查 GPU 电源投票；中断处理只清自己处理的位，GMU 启动前先屏蔽中断再按阶段打开。
- 适用范围：高通 Adreno + GMU；2026。

### GPU 故障恢复永久卡住
- 现象：恢复线程停在 `a6xx_gmu_set_oob()`，SMMU fault 线程在等 `msm_gpu_fault_crashstate_capture()` 需要的 `gpu->lock`。
- 原因：恢复线程持锁等 devcoredump 完成，dump 又要拿同一把锁。
- 怎么解决：等待加上限，超时后报告并让恢复继续、释放锁（上游有对应修复，先查是否已合入）。这只防住死锁，不修最初的 GPU 故障。
- 适用范围：主线 msm；2026。

### GPU 已经降频，内存频率仍被钉在高档
- 原因：内核启动时按 GPU OPP 设了带宽票；GMU 接管带宽管理之后，频率路径不再走 OPP 更新，旧票一直留到 GPU 关电。
- 怎么确认：同样负载下对比互连投票和 DDR 状态。
- 怎么解决：GMU 成功接管带宽后撤掉内核的启动票。只适用于 GMU 自己管带宽的路径。
- 适用范围：高通 Adreno；2026。

### 多个 GL 上下文同时创建时崩溃（共享上下文竞态）
标记：【耗时】
- 现象：设置里有多个视频演示的页面一打开就崩，`SIGSEGV in _mesa_release_pending_resource` ← `delete_buffers`。
- 原因：Mesa 通用 GL 前端在新上下文的状态跟踪器就绪前就把它挂进共享列表；threaded context 下遍历共享列表时读到空指针。freedreno 总是启用 threaded context，所以必现；发行版 Mesa 走软件渲染反而不复现。
- 怎么确认：core 里找到正在创建的上下文；写一个并发创建、销毁上下文的压力用例，原版崩、修正版不崩。
- 怎么解决：新上下文就绪后再入列；向上游提交最小修正。`GALLIUM_THREAD=0` 能绕过但有性能代价。
- 适用范围：Mesa 26.x 及之前，GL 前端通用问题；2026。

### GTK Vulkan 渲染器下 NV12 视频和相机预览出现斜纹
标记：【耗时】
- 现象：GTK 应用里的 NV12 视频、相机预览有斜条纹；GL 渲染器正常。
- 原因：Turnip 在 A8xx 上 buffer→image 上传的行距单位错误（上游 stable 已修，自编版本缺这个提交）。
- 怎么确认：无窗口复现器跑全部模式；临时修改行距系数做正反因果对照。
- 怎么解决：回移上游修复；同时检查 snap GPU 提供者是否也更新。修好之前相机可以临时输出 BGRx 绕过（CPU 开销明显，NEON 转换可以减半），修好后退回 NV12。
- 适用范围：Mesa Turnip A8xx；2026。

### 视频播放器播放时 Mesa 断言退出
- 现象：`fd6_texture.cc ... [CHIP = A8XX] ... Assertion` 后 SIGABRT。
- 原因：threaded context 下纹理序号分配器没有加锁，两份仍在使用的纹理拿到同一个序号，状态缓存命中了错误的纹理。不是格式支持不完整。
- 怎么解决：改用线程安全的分配器（`util_idalloc_mt`），保留序号 0 的特殊含义；用并发压力用例和真实播放器验证。
- 适用范围：freedreno A8xx，Mesa 26.x；2026。和上面的共享上下文竞态是两个问题。

### 某个代际的 GMEM 基址返回值错误，浏览器和 Electron 应用花屏
- 原因：内核对某代 GPU 跳过了 GMEM 范围设置却返回了错误的基址。
- 怎么确认：把真实应用调用缩成原生 GLES 最小用例；用驱动调试开关（例如 `FD_MESA_DEBUG=sysmem`）对照；用 LD_PRELOAD 拦截参数查询做单变量。
- 怎么解决：内核一行修复（上游已有）；修复后撤掉应用层的绕过参数。
- 适用范围：Adreno 7xx；2026。

### Vulkan 在新 GPU 上挂起
- 现象：`vkcube` 触发 `hangcheck detected gpu lockup`。
- 怎么解决：先查上游 Turnip 对该代际的修复；修好之前不默认启用 Vulkan 应用，GTK 先用 GL 渲染器。
- 适用范围：Turnip 新代际的早期版本；2026。

### 在 QEMU 或软件渲染下"通过"
- 原因：Mesa 自动退回 softpipe/llvmpipe，像素检查照样通过。
- 怎么解决：测试断言渲染器名称是硬件 GPU，并准备一个要求硬件 GPU 的负例。
- 适用范围：通用。

### 帧测试拿不到画面
- 原因：GDM 登录界面不出应用帧；线性抓帧工具拒绝高通压缩格式。
- 怎么解决：帧测试用一个带明确尺寸的无头 GNOME 会话（例如 `gnome-shell --wayland --headless --virtual-monitor 1920x1080`），结果和物理会话分开记录；不要拿光标平面冒充主画面。
- 适用范围：GNOME；2026。

## 未解决
