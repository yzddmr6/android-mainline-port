# 内核配置、资源归属与设备树数值

## 推荐路线

1. **基线**：最新稳定版内核加明确来源的补丁（上游在审系列、社区按提交导入）。上游合入后换成正式版本并删除本地实现。
2. **设备树**：上游 SoC dtsi 加自写板级文件。每个数值从本机原厂证据推导（运行时设备树、PMIC 寄存器、原厂 debugfs、厂商源码），不复制参考设备的值。
3. **内建与模块**：启动、恢复、调试通道需要的驱动，以及借用固件画面依赖的资源提供者，编进内核或完整放进 initramfs；其他按上游默认做模块，发布完整模块目录。
4. **固件留下的资源**：每个仍在使用的时钟、电源域、总线带宽，都要在设备树里有真正的消费者，并且消费者在内核回收之前绑定。
5. **配置对齐发行版**：首版前把内核配置和发行版通用内核对比一遍，补齐桌面常用项。

## 完成标准

- 最终 `.config` 里关键项的实际值正确，且对应 `.ko` 确实在模块目录里、确实被加载。
- `devices_deferred` 为空或每项可解释。
- 没有长期挂起的 sync_state；没有 `*_ignore_unused`、`fw_devlink.sync_state=timeout`、屏蔽部分模块之类的全局绕过。
- 用完整模块集、无黑名单的情况下多次冷启动稳定。

## 坑

### 驱动编成 `=m`，但镜像里没有模块目录，功能静默缺失
标记：【高频】【耗时】
- 现象：永久 `EPROBE_DEFER`、驱动不绑定、电源键和音量键失效、远端处理器服务不出现、`reboot bootloader` 失效，但没有任何报错。
- 原因：早期 RAM 镜像只有 Image + DTB + 小 initramfs，没有 `/lib/modules`；后期有模块目录时又出现"提供者一半 `=y` 一半 `=m`"。
- 常见受害者（高通）：`QCOM_GPI_DMA`（SPI 触控）、`QRTR`/`QRTR_SMD`/`QCOM_PD_MAPPER`（ADSP 服务）、GPU 时钟控制器（GPU 整条链等待）、`PHY_QCOM_QMP_PCIE` 与 `RFKILL`（Wi-Fi）、`POWER_RESET_QCOM_PON`（电源键和音量键）、`RTC_DRV_PM8XXX`、`NVMEM_REBOOT_MODE` 及 `NVMEM_SPMI_SDAM`、`BATTERY_QCOM_BATTMGR`、`QCOM_CPUCP_MBOX`（没有调频）、Type-C 切换芯片驱动（拖住整个显示驱动）、`OVERLAY_FS`、`SPI_QCOM_GENI`、`FASTRPC`、`SND_SEQUENCER`。
- 怎么确认：怀疑设备树之前，先看最终 `.config` 的实际值、模块目录是否交付、`lsmod`、`devices_deferred`。
- 怎么解决：首启阶段把启动和恢复依赖全部 `=y`；尽早建立"版本化完整模块目录"的交付方式；根启动、恢复、显示组件依赖链整链内建。
- 提前预防：注意 `A depends on B || !B` 的传导：B 是 `=m` 会把 A 也压成 `=m`（例如 RFKILL 把整个无线链变成模块）。
- 适用范围：通用；高通符号写于 2026。

### 固件仍在用的资源没有消费者，被内核回收
标记：【高频】【耗时】
- 现象：借用固件画面一段时间后黑屏或灰屏；GPU 的 GMU 超时、hangcheck；触控 SPI 超时；多数情况重启也不恢复。
- 原因：内核在 `late_initcall`（`clk_disable_unused`）和 sync_state（genpd、interconnect、rpmhpd）时关掉没有消费者的资源。固件留下的显示时钟、电源域、总线带宽没有人在设备树里声明在用。
- 怎么确认：在回收前后各导出一次 `/sys/kernel/debug/clk/clk_summary`、`pm_genpd_summary`、`interconnect_summary` 对比；看哪些在回收后被关掉。
- 怎么解决：在真正的消费者节点（例如 simple-framebuffer）里声明电源域、时钟、互连路径及带宽；提供者驱动内建并在回收前绑定。
- 提前预防：不要用 `clk_ignore_unused`、`pd_ignore_unused`、`fw_devlink.sync_state=timeout`、`iommu.passthrough=1` 把问题盖住。它们能让你快速出图，但以后无法省电、无法休眠、无法进上游。可以短时间当诊断手段用来确认"是不是资源回收"，确认后撤掉。
- 适用范围：通用，高通尤其明显；2026。

### 显示时钟控制器编成模块，出现"慢启动态"
标记：【耗时】
- 现象：大部分启动一切正常，少部分启动之后 GPU 超时、触控超时、整体变慢，而且同一次启动内不会恢复；单次检查发现不了。
- 原因：显示时钟控制器（例如 dispcc）是模块时，借用画面的驱动约 15 秒才绑定，而显示总线时钟在 2–3 秒就被回收，内存通路降速，之后再接上也不复原。
- 怎么确认：看 simpledrm 绑定时刻与 `clk_disable_unused` 时刻；做内存带宽小测试；看多次冷启动。
- 怎么解决：把显示时钟控制器编进内核。
- 提前预防：修改借用画面相关的资源时，同时核对提供者是否内建、绑定时刻是否早于回收；验收加时间和带宽预算（见 `../references/verification.md`）。
- 适用范围：借用固件画面的路线；2026。

### 用部分模块黑名单或裁剪模块目录"保住"引导状态，引发无日志重启
标记：【致命】
- 现象：随机整机复位，pstore 为空。
- 原因：部分提供者不加载，部分 sync_state 永远挂起，系统处在一个从未验证过的中间状态。
- 怎么解决：不要这样做。裁剪只用于诊断，用完恢复完整模块目录；资源需求写进真正的消费者。
- 适用范围：通用。

### 黑名单被依赖加载绕过
- 现象：已加入黑名单的旧驱动仍然被加载。
- 原因：其他模块通过依赖 `modprobe` 拉起它（黑名单只挡别名自动加载）；或黑名单写在命令行被截断。
- 怎么解决：用 `install <模块> /bin/false`，或在 udev 之前交付正确的模块目录；不要把长黑名单放命令行。
- 适用范围：通用。

### 设备树里的电压不在 PMIC 驱动允许的步进上，整颗 PMIC 的所有电源消失
标记：【高频】【致命】
- 现象：加了一路电源后，显示、USB 甚至调试通道全部消失；需要人工恢复。
- 原因：厂商写的标称值（例如 3.300 V、1.900 V）落不到主线 regulator 驱动的电压表（例如 8 mV 步进），`min = max` 无解，整个 PMIC 的 regulator 注册失败。
- 怎么确认：按驱动里的 linear range 计算该值能否表示。
- 怎么解决：在原厂系统里只读 PMIC 的电压寄存器得到实际值（例如 3296 mV、1896 mV），设置一个包含它的窗口。
- 提前预防：所有 `min = max` 的电压在构建时机械校验。
- 适用范围：高通 RPMh regulator；通用方法。

### 原厂常开的电源在主线没有声明，外设总线在任何通信之前就是低电平
标记：【耗时】
- 现象：外设（例如磁吸键盘桥）能枚举但没有数据，查询命令全部超时；修协议层无效。
- 原因：原厂设备树里某些 LDO 是 always-on，名义消费者是别的子系统（例如显示），主线没有声明，于是总线上拉没电。
- 怎么确认：读串行控制器的线路状态寄存器和 GPIO 输入电平（注意 pinctrl 调试接口显示的是输出锁存，不是输入）。
- 怎么解决：把原厂所有 always-on/boot-on 电源与运行时 `regulator_summary` 做差集，补上缺失的。
- 适用范围：通用方法。

### 串行引擎的父包装器或 GPI DMA 没启用，控制器不出现
标记：【高频】
- 现象：I2C/SPI/UART 子节点已启用，但适配器从未注册，或 SPI 永久 defer 并拖住其他 sync_state。
- 原因：`qupv3_N` 父包装器节点 disabled；`gpi_dma` 节点 disabled 或 `QCOM_GPI_DMA=m`。
- 怎么解决：启用任何串行引擎时同时检查三层：包装器节点、GPI DMA 节点、DMA 驱动内建。
- 适用范围：高通；2026。

### OPP 返回 `-ERANGE` 后电源投票永久丢失
- 现象：亮屏或恢复后几十毫秒内整机静默挂死。
- 原因：为了通过模式校验把时钟上限抬到 OPP 表之外，`dev_pm_opp_set_rate` 返回 `-ERANGE`，关闭后电源域投票归零且不再恢复；运行时恢复先开时钟后投票。
- 怎么解决：请求频率钳到 OPP 表顶；恢复时先投票再开时钟；不要用临时常持的时钟引用对抗回收。
- 提前预防：`-ERANGE`、"找不到 OPP"不是噪声。
- 适用范围：通用。

### 新驱动第一次 probe 就编进内核，出问题时整机挂死
- 现象：一次性启用多个多媒体驱动后，几张镜像都黑屏、没有 USB。
- 原因：没人跑过的时钟控制器或驱动在启动早期挂住总线。
- 怎么解决：第一次测试编成模块，在调试通道建立后手动加载；通过后再决定是否内建。
- 适用范围：通用。

### 读调试接口本身改变了系统状态
- 现象：加了只读采集后问题消失或出现新问题。
- 原因：读 `clk_summary` 会唤醒某些子系统；`cat` 某些 sysfs 会触发多次总线传输；读已断电模块的寄存器会挂死。
- 怎么解决：观测前确认副作用；对照组加同样的采集代码；运行时电源相关的读取要先持有电源引用。
- 适用范围：通用。

### 调试选项会改结构体布局，按另一份配置编的模块静默写坏内存
标记：【致命】【耗时】
- 现象：换自编内核后系统在启动用户态时挂死或几十秒后硬复位，同一份 rootfs 在参考内核上正常；`modprobe` 不报错，`vermagic` 也一致。
- 原因：`CONFIG_NETCONSOLE` 会选上 `CONFIG_NETPOLL`/`NET_POLL_CONTROLLER`，`struct net_device` 因此多一个字段；按旧配置编出的模块以为结构体更小，写尾部字段时踩到别的对象。`CONFIG_MODVERSIONS` 关闭时只有 `vermagic`（版本与几个配置前缀）参与校验，这种差异检测不到。
- 怎么确认：用 `scripts/extract-ikconfig` 从设备上正在跑的内核镜像抽出配置，与自编的 `.config` 逐项对比（不要只看版本号）；对可疑结构体用 `pahole` 或 `gdb` 比 `sizeof` 和字段偏移。
- 怎么解决：以设备上现有模块对应的真实配置为基线重编，或关掉所有会改结构体的调试选项（netconsole、额外的 trace/hook）再编；内核与模块必须来自同一次构建。
- 提前预防：把"只加调试输出"的选项也当 ABI 变更处理；构建脚本里加一步，目标机上 `extract-ikconfig` 的结果与本地产物 `.config` 不一致就拒绝上机。
- 适用范围：通用（内建模块 ABI）；2026。

### 反编译设备树时，整数被显示成 phandle 标签
- 现象：数值看起来是一个不相关的节点名。
- 怎么解决：数值只用 `dtc -I dtb -O dts` 的原始输出核对，不用美化工具。
- 适用范围：通用。

### UDC 重建时 `-ENOENT`，USB gadget 恢复不了
- 现象：USB 角色切换或 gadget 重建后报 `kobject_move` 失败。
- 原因：`device_move` 成功路径泄漏旧 glue-dir 引用（设备模型层的上游问题）。
- 怎么解决：上游补丁修复引用计数；先检查上游是否已合入。
- 适用范围：主线 7.x；2026。

### 内核配置缺桌面常用项
- 现象：蓝牙 LE 键鼠不工作（缺 `UHID`）；没有内存压力保护（缺 `PSI`、zram）；防火墙、WireGuard 不可用；`.zst` 压缩固件读不了（缺 `FW_LOADER_COMPRESS`）；snap 挂载失败（缺 SquashFS XZ/LZO/XATTR）；ALSA 钩子要求 `snd-seq`。
- 怎么解决：首版前与发行版通用内核配置逐项对比，按功能单独提交，方便回退。
- 适用范围：桌面发行版；2026。

### `MODVERSIONS` 关闭时，模块 ABI 破坏无法检测
- 现象：同名内核版本的旧模块被新内核加载，行为异常。
- 怎么解决：每个打包的内核构建都升一个版本号（ABI），从不复用，见 `ubuntu-userspace.md`。
- 适用范围：通用。
